# Project Notes

## Plain-English Goal

The project asks you to find actor groups that repeatedly appear together across
movies. In market-basket language, each movie is a transaction and each actor is
an item. Frequent itemset mining then answers: "Which actors co-occur more often
than a chosen minimum support threshold?"

## Why This Exists In The Real World

Market-basket analysis is used when organizations want to discover repeated
co-occurrence patterns:

- retail products bought together;
- banking products held together by the same customer;
- merchants or card-spend categories that co-occur in customer behavior;
- fintech user actions that predict later conversion;
- fraud indicators that repeatedly appear in suspicious cases.

The IMDB dataset is not financial, but the algorithmic idea transfers directly
to finance and product analytics.

## Finance Angle For The Report

Use the finance connection as interpretation, not as a fake claim about the
dataset. A good sentence for the report would be:

"Although the empirical dataset concerns actors and movies, the same frequent
itemset framework is used in financial services to discover product affinities,
merchant-spend bundles, and repeated combinations of behavioral signals."

## What To Avoid

- Do not frame this as a prediction model.
- Do not overclaim causality.
- Do not submit code generated by AI tools.
- Do not commit Kaggle credentials or raw downloaded data.
- Do not rely only on one threshold; the experiment should show how the method
  behaves under different settings.

## Course-Relevant Methods To Consider

- Apriori: uses the downward-closure property to prune candidates.
- PCY: uses hashing to reduce the number of candidate pairs.
- SON or MapReduce-style decomposition: useful if you want to emphasize
  distributed scalability, even if the assignment dataset itself is small.
